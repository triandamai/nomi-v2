# Decks with HyperFrames slideshow

A slideshow is a normal composition (the whole contract in `video-hyperframes` applies) plus one JSON island that says which scenes are slides and how they connect. The deliverable is a **running deck** someone clicks through, with reveals, branches and speaker notes. It is not an MP4.

Use it when someone presents: a pitch to an investor, a proposal to a client, a menu tasting talk, a class. When it should play start to finish with nobody presenting, make a video instead.

## What changes from a video

- **Each slide is a top-level scene** in the composition file, with `data-composition-id`, `data-start`, `data-duration`, `data-label`, `data-width` and `data-height`. No master root composition wraps them.
- **One island per composition**, near the top of `<body>`, written in the HTML and never generated by script (the presenter reads the file statically):

```html
<script type="application/hyperframes-slideshow+json">
{ "slides": [
    { "sceneId": "hook", "notes": "Berhenti sebentar di angka ini." },
    { "sceneId": "problem", "fragments": [11.0, 15.0],
      "hotspots": [{ "id": "h1", "label": "Dari mana angka ini?", "target": "detail",
                     "region": { "x": 55, "y": 60, "w": 40, "h": 20 } }] } ],
  "slideSequences": [
    { "id": "detail", "label": "Cara hitung", "slides": [{ "sceneId": "detail-math" }] } ] }
</script>
```

## The model

| Part | How it works |
|---|---|
| Slide | `sceneId` equals a scene's `data-composition-id` (or give `startTime`/`endTime`). Main-line slides never overlap in time. |
| Fragment reveals | Absolute timeline times, on the same clock as `data-start` (not offsets inside the slide), within the slide's start and end. Each click seeks to the next fragment. |
| Rest frames | Navigation **seeks, never plays**. Every hold state must look right when the timeline is seeked straight to that time. A slide without fragments enters at a rest frame inside it. |
| Branching | Branch slides are ordinary scenes listed only in `slideSequences`, never in the main `slides` array. A hotspot's `target` is a sequence `id`. Back returns to the slide that held the hotspot. |
| Hotspot region | A percentage box (`x`, `y`, `w`, `h`) over the slide. Omit it for a full-slide button. |
| Presenter mode | `notes` are presenter-only. In present mode the presenter sees the live slide, the notes, what comes next and a timer; the audience tab shows the clean slide. |
| Reserved | `ttsScript`, `ttsAudioUrl` and `ttsDurationMs` are not wired yet. Don't use them. |

The `<hyperframes-slideshow>` element wraps a `<hyperframes-player>` and owns Present (P), Prev/Next, the counter, mute, fullscreen, swipe, hotspots, editable presenter notes and stopping media when a slide exits. Don't build your own versions of any of these.

## How a good deck is built

- **One claim per slide**, with one visual that proves it. The headline is a complete-sentence claim, not a label ("Pelanggan kembali 3× sebulan", not "Retensi"), and it comes from the brief's real numbers.
- **Reveals** only where the presenter adds an idea piece by piece. Three pain points arriving one at a time is a good use.
- **Branches** for optional detail (how a number was calculated, a price breakdown), so the main story works if nobody opens them.
- **Speaker notes** that help the presenter rather than repeat the slide.
- Text the audience must read is at least **40 px at 1920×1080**.
- Keep the bottom-right corner of about 360×140 px clear, where the navigation capsule sits.
- Use the brand's `frame.md` (`video-hyperframes-frame-md`). The 13 HyperFrames frame presets are deck looks, but the client's own tokens win.
- Search the registry before hand-building any named visual (`video-hyperframes-registry`).

## Porting an existing page into a deck

- Keep the source's look, motion, interactions and media.
- Movement the page drove by scrolling becomes a camera move from one focal point to the next on navigation, never a page visibly scrolling.
- Screenshots, charts and images with readable text keep their aspect (`object-fit: contain`). Check all four edges for crops.
- Every `<video>`/`<audio>` needs `data-start` and `data-duration` (`data-has-audio="true"` when its sound plays), and no `preload="none"`.
- Hidden stacked slides need `opacity: 0`, `visibility: hidden` and `pointer-events: none` together, or an invisible layer swallows clicks.
- Replace font CSS variables used as `font-family` values with real families, or add `@font-face`.

## Presenting and handing off

- **Never render a deck to MP4.** It doesn't fail: with no master root, the render resolves only the first slide and writes a silently truncated file. For stills, snapshot each slide (`npx hyperframes snapshot --at <time>`); for a PDF-like hand-out, export those stills.
- `npx hyperframes check --json` must be clean. Its slideshow rule checks that every `sceneId` resolves, every hotspot `target` exists, fragments sit inside their slide, and main-line slides don't overlap (`slideshow_invalid`, `slideshow_unresolved_ref`).
- The deck is served with `npx hyperframes present <project-dir>`. The person clicks Present or presses P to open the audience tab. In Google Meet, share the audience **tab**. In Zoom, drag the audience tab into its own window and share that window, because a fully covered window freezes.
- In Nomi, the Design Studio plays the deck's composition in its iframe. If present mode isn't available there yet, say so, and hand off the checked deck plus per-slide stills rather than an MP4.
